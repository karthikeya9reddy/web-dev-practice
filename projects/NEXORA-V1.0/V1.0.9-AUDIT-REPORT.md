# NEXORA V1.0.9 — Mobile & Fluidity Audit

## Executive result

The targeted repairs are implemented and the release passes 50/50 automated tests plus 6/6 Chromium browser checks. JavaScript syntax checks passed and PostCSS parsed the stylesheet with zero errors. The server and core player/application behaviour were checked against the preserved V1.0.8 source. A physical Android test remains outstanding.

## Findings and resolutions

### 1. Mobile fullscreen framing

The fullscreen player stage is pinned to the dynamic viewport with a `100vh` fallback and `100dvh`, with safe-area-aware controls. The video is centred and uses `object-fit: contain`, avoiding source cropping. Fullscreen requests ask the browser to hide its browser chrome where supported and request landscape orientation on touch phones where the platform allows it.

Chromium loaded real generated WebM clips and entered fullscreen at 915×412 landscape for 16:9, 4:3 and 21:9 source ratios, and at 412×915 portrait for 16:9. All stage rectangles matched the viewport and all source ratios remained fully contained. See `MOBILE-FULLSCREEN-AND-NAV-AUDIT.md` and `BROWSER-AUDIT/`. Android OS bars can still depend on browser and vendor immersive-mode policy; a physical phone test is required.

### 2. Wrapped mobile navigation

The indicator is measured using the selected button's x/y offsets and width/height. A Chromium test deliberately constrained the navigation to 170px at a 345×800 viewport so Anime sits on the second row. After the animation settled, the indicator measured 66×36px and its transform exactly matched the selected button offset (5,44). It no longer becomes a vertical capsule across multiple rows.

### 3. Live ambience temporal smoothness

The existing hero preview remains the single video decoder. The sampling interval is capped at 33ms on capable devices, 40ms on constrained devices, and 50ms when Save-Data is enabled; reduced-motion preference keeps a much slower decorative cadence. Adjacent decoded frames are blended using elapsed time and a 44ms normal / 54ms constrained temporal constant. The dual-layer ambience handoff remains opacity-based, and callbacks/timers are cancelled when the preview changes or stops. Automated tests cover frame sampling, history-buffer blending, palette smoothing and cancellation.

This code/runtime test verifies the pipeline and bounded cadence; continuous capture on the user's own Android GPU is not available in this environment.

### 4. Scroll workload

Poster-grid insertion is limited to 32 cards per synchronous batch instead of 64; the 680px observer prefetch distance remains unchanged. The 97-title deterministic test confirms batches `[32,32,32,1]`, with every title preserved in order. The Chromium synthetic 32-card scroll fixture completed four warmed-up two-second trials, each recording 121 frames, a median interval of approximately 16.7ms, p95 intervals of 16.7–16.8ms and zero Long Task entries during the measured scroll interval.

The audit harness was corrected after an earlier measurement used `PerformanceObserver` with `buffered: true` after warm-up, which could include prior page-setup tasks in the scroll result. The current observer starts without buffering and measures only tasks during the scroll interval. This is a 60Hz Linux host-browser measurement, not proof of 120fps or a benchmark on the user's phone. Real-library image decoding, media load and thermal behaviour still need device profiling.

## Functionality freeze

`FUNCTIONALITY-FREEZE-VERIFICATION.json` records all source-diff checks. `server.js` is unchanged after release-label normalization. The only `script.js` logic changes are the ambience renderer's frame cadence/temporal blending and the poster batch size, plus adjacent explanatory comments. `index.html` only updates cache-busting release versions. `style.css` only updates the release comment relative to V1.0.8. Package dependency names/versions and the lockfile dependency graph are unchanged. No sign-in/authentication or custom text-selection styling is present.
